Unused-code removal matters. The unused-code-removal configuration re-links the exact cached Rust archives and identical Swift host with -dead_strip. Rust is not rebuilt. This removes unreachable linked code; strip -S -x alone removes symbol information. The original build metadata identifies the unchanged sources, while separate relink provenance records the additional flag and input/output hashes.

ZIP contains only the app bundle. Executable gzip contains only the executable. These two compressed numbers have different contents and must not be interchanged. A MiB is 1,048,576 bytes.

How to use these numbers

For this macOS integration: prefer the unused-code-removal plus symbol-stripping lane for size planning, after its correctness checks. Keep both renderer and linker settings pinned. Use the baseline increments to understand the extra linked code in this harness. They are stronger evidence than comparing an unrelated debug drawing app with a combined release benchmark.

For a production application: removing benchmark instrumentation, changing renderer features, linking Skia directly to Metal, adding fonts/codecs or changing optimization can alter the result. Skia’s enabled JPEG/PDF features do not establish their retained size; unused code can be removed by the linker. Static library size is not app size.

For iOS/iPadOS, Android or web: do not reuse the macOS deltas. Architecture, graphics backend, linker, language runtime, shaders and delivery compression differ. Those targets require their own separate builds.

These are local arm64 applications with ad-hoc signatures. They are not universal binaries, notarized releases, App Store download measurements, RAM usage or performance results. Size does not change the qualified performance findings or settle the production renderer decision.
